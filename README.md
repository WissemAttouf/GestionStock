# Stock Management System

A web-based stock management application built with **ASP.NET Core MVC**, **Entity Framework Core**, and **SQLite**. It provides a product catalog with create, read, update, and delete operations, text search, and a dashboard with stock summary figures.

## Features

- **Product CRUD** — create, view details, edit, and delete product records.
- **Product search** — filter products by name, description, or category.
- **Stock overview** — display the number of products, total quantity in stock, and estimated stock value (unit price × quantity).
- **Low-stock visual indicators** — highlight quantities of 5 or fewer, quantities from 6 to 10, and quantities above 10.
- **Product metadata** — maintain a name, optional description, price, quantity, optional category, and creation date.
- **Responsive interface** — Bootstrap-based layouts, tables, forms, icons, and status messages.
- **Local database** — SQLite stores data in a local database file.
- **Sample data** — on startup, the application inserts four example products when the Products table is empty.

> **Scope:** This repository implements product and stock-record management. It does not currently show authentication, user roles, supplier management, purchase orders, sales processing, barcode scanning, or a separate REST API.

## Application overview

The default route opens the product listing:

- `/` — redirects through the default MVC route to `Products/Index`
- `/Products` — product list and search
- `/Products/Details/{id}` — product details
- `/Products/Create` — create a product
- `/Products/Edit/{id}` — edit a product
- `/Products/Delete/{id}` — confirmation and deletion flow

The application uses conventional MVC routes; these are web pages and form actions, not a documented REST API.

### Product fields

| Field | Description |
| --- | --- |
| `Id` | Primary key generated by the database |
| `Name` | Required product name |
| `Description` | Optional description |
| `Price` | Product unit price |
| `Quantity` | Quantity currently in stock |
| `Category` | Optional product category |
| `CreatedAt` | Date and time when the product was added |

The dashboard calculates the stock value by summing `Price × Quantity` across the products currently displayed by the controller. When a search filter is active, the displayed summary figures are calculated from the filtered list.

## Architecture

The application follows a straightforward ASP.NET Core MVC structure:

```text
.
├── Controllers/
│   └── ProductsController.cs
├── Models/
│   └── Product.cs
├── dta/
│   └── ApplicationDbContext.cs
├── Migrations/
├── Views/
│   ├── Home/
│   ├── Products/
│   │   ├── Index.cshtml
│   │   ├── Details.cshtml
│   │   ├── Create.cshtml
│   │   ├── Edit.cshtml
│   │   └── Delete.cshtml
│   └── Shared/
├── wwwroot/
│   └── css/
├── Program.cs
├── FirstProject.csproj
└── FirstProject.sln
```

- **ProductsController** handles product listing, search, details, creation, editing, and deletion.
- **Product** defines the product fields and data annotations.
- **ApplicationDbContext** exposes the `Products` entity set to Entity Framework Core.
- **Razor views** render the user interface.
- **Migrations** contains EF Core migration files.

## Getting started

### 1. Clone the repository

```bash
git clone https://github.com/WissemAttouf/GestionStock.git
cd GestionStock
```

### 2. Restore dependencies

```bash
dotnet restore
```

### 3. Run the application

```bash
dotnet run
```

Open the local URL printed in the terminal. The actual HTTP/HTTPS port is selected by the ASP.NET Core launch configuration or runtime environment; check the console output rather than assuming a fixed port.

### 4. Database behavior

At startup, `Program.cs` configures Entity Framework Core to use:

```text
Data Source=FirstProject.db
```

The application calls `Database.EnsureCreated()` and seeds four sample products if the Products table is empty. The database file is local to the application's working directory and is ignored by the repository's `.gitignore`.

**Important:** `EnsureCreated()` is not the same as applying EF Core migrations. If you change the model later, review the database initialization strategy before relying on migrations to update an existing database.

## Current implementation notes

The following details are documented to keep expectations aligned with the source code:

- The application currently configures **SQLite** directly in `Program.cs`; it does not read a database connection string from configuration.
- Product search is performed after loading products from the database, so it filters the retrieved collection in application memory.
- The dashboard's stock value uses the current .NET currency format (`ToString("C")`), which depends on the runtime culture.
- The current code does not configure authentication or authorization policies. Do not expose the application publicly with the assumption that product operations are restricted to authorized users.
- The repository includes generated `bin/` and `obj/` content in its current tree. Build artifacts generally should not be committed; the existing `.gitignore` already lists these directories for future changes.
- The project includes EF Core migration files, while startup uses `EnsureCreated()`. Choose one consistent database initialization approach before expanding the schema.
